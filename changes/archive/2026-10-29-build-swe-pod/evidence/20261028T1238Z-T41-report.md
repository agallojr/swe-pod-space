## Concerns
- T10.TS6 run 4 fails check 1 on how the check reads blocks, not on the
  agent's commands. Printing at the point of each command, the agent
  printed its `DESK: ` lines in three pieces between tool calls, then the
  whole list again in its final reply, in the right order with one commit
  per record. The first piece (record 1, from the first fetch to the
  `log -1` after the rebase) is in no reply text of the stream: that turn
  came through only as an empty thinking block. The check therefore read
  first a block that starts at record 1's push and holds record 2's commit,
  then the closing list, which is not a pure repeat of what it had read,
  so it read record 2's commit twice: 3 commits. A fix would be in the
  T10.TS6 check (outside this task's lane), for example taking the final
  reply's `DESK: ` lines as the sequence when they hold every earlier
  block, in order.
- The new wording leads agents to print `DESK: ` lines between tool
  calls, at each point, rather than in one block at the end, so any check
  that reads every block is more exposed to the case above. In all nine
  runs the final reply holds `DESK: ` lines for the commit, the push and
  the closing ancestor check, and no `FILED` line.
- Only the three librarian tests and smoke were run with the new wording;
  the other agent-mode tests, which carry the same preamble, were not
  rerun here.
