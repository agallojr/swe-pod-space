- **Heavy.** Each test is `expected_s: 240`, `cap_s: 600`, `heavy: true`.
  At verify, each needs the operator's go and `--allow-heavy`. That is two
  lead runs of about 4 min each, run serially.
- **Space commit.** A copy with no git history cannot show which space
  commit holds the latest shard briefs. The lead can work it out only from
  the ledger's filing order and the shard records' `commit_set`. The checks
  therefore require the alpha and beta heads, and check the space sha only
  when the answer names one (`8b8b8b8`).

    the fixture to two all-pass records and a clean review.

  A lead may remark on any of these. That does not change the expected
  state.

## Test suggestions

### T39.TS1 Shards at one commit set that together miss a result
- for the tester: R24 is at risk when two shard records name the current
  commit set and every result in them is a pass, but together they cover
  no result for one scenario (for instance R2.S1) or one unit suite. The
  change should not be verified. A lead that checks only "same set, all
  pass" would call it verified.
- for the reviewer: the verified rule in `PROCESS.md` §7 and §11 and in the
  swe-lead definition. Check that it requires the shards to cover every
  scenario, unit suite and declared quality check, not only to agree on the
  commit set.

### T39.TS2 A shard re-run supersedes its own earlier record
- for the tester: R24 with two records for one shard. T7b fails at the old
  set and passes at the current set, and T7a passes at the current set. The
  change is verified, because each shard's latest record is used. A lead
  that counts every record would see the old failure and refuse.
- for the reviewer: where `PROCESS.md` §7 says to take each named shard's
  latest record.

### T39.TS3 Status and trace for a stale shard
- for the tester: R20 and R24. With the R24.S2 records, a regenerated
  `STATUS.md` should not show `state: verified`, and the trace should
  report the stale shard's record (`BREAK evidence-stale <ev id>`).
- for the reviewer: `skills/swe-pod/status-format.md`, on the latest
  evidence bullet when verify is sharded, and how the skill decides that a
  shard record is stale.
