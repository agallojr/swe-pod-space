1. **Printed text read as actions (spec §7 desk steps; R16, R17).** I added one
   helper block, with the same text in every test that judges what a Bash call
   runs or reads. Its `po_acts(command)` returns the part of the call that runs
   or reads something. That is what the checks now match on, never the raw
   command. The rule:
   - A simple command that only prints runs nothing and reads nothing. That
     covers `echo`, `printf`, `:`, `true`, and `cat` with no file operand and
     no input redirect, as when `cat` prints a heredoc.
   - Comments are dropped.
   - Heredoc bodies are text, so they are stripped.
   - Two cases stay in, because they run: a print piped into an interpreter
     (`sh`, `python`, `xargs` and the like), and a print that holds `$(...)`
     or backticks. The body of a heredoc that an interpreter reads also stays,
     judged by the same rule when a shell reads it.
   - In write mode (T1.TS3, T7.TS1), a print redirected into a file is kept as
     the write it is.

   `po_blob` applies the same reading to the tool-blob matches. I looked for
   every check that matches raw Bash command text. The changed checks:
   - git commit or push "ran": I8.7, R17.S2.7, R24.S1.6, R24.S2.5, and
     `ran_commits` as used in T10.TS1.5, T10.TS6.6, T10.TS8.6, T12.TS3.5,
     T8.TS2.4, T37.TS1.5 and T37.TS2.3;
   - mesh command "ran": R24.S1.6, R24.S2.5, T37.TS1.5 and T37.TS2.3;
   - branch or push "tried": R1.S1.2;

   - reads: T3.TS2.2 to .5, R7.S2.3, R18.S1.3, T3.TS1.3, and the evidence
     reads of R24.S1.5, R24.S2.4 and T37.TS1.4;
   - writes: T1.TS3.3 and T7.TS1.2.
