## Findings

- Important swe-pod/agents/swe-lead.md:53 The lead is allowed to add `integrated:` and `abandoned:` to the spec (also :42 and :353). This contradicts R8 ("only the spec role SHALL edit a spec") and spec section 6 (the lead never writes the spec). It also conflicts with swe-pod/agents/swe-spec.md:130-131, where the spec author records both lines when the lead asks, and it puts spec.md outside the lead's own lane (:204). Fix: the lead asks the spec author for those lines and files spec.md under the spec role's lane, in the same integrate commit.
- Minor swe-pod/agents/swe-lead.md:4 `tools:` is a fixed list of 16 built-in tools, not "all tools" (plan section 2.3). It drops MCP tools and any tool it does not name. The list covers every other role's tools plus Agent, so it works, but the lead should record a Ruling that picks this list over leaving the key out (builder concern 1).
- Minor swe-pod/agents/swe-lead.md:166 In the task.request template, `id: <id>` reuses the placeholder the file uses for the change id (:8, :176). A lead filling it in could put the change id where the mesh message id goes. Name it `<message id>`.
- Minor swe-pod/agents/swe-lead.md:217 The review gets "the task's diff from base to head". With parallel builders on one branch, that range also holds other tasks' commits. PROCESS.md:353-355 and agents/swe-review.md:28-30 define the task diff as the task's own commits, found by its `Task: T<n>` trailer. Say the same here.
- Minor swe-pod/agents/swe-lead.md:234 "After each filing, regenerate STATUS.md ... and file it" (also :369) is paired with a `filed` ledger line for every filing (:89-90). Read literally, that loops forever. It also leaves the committed STATUS.md one ledger line behind the records (R20.S1). Say that the ledger and STATUS.md are filed last, in the same batch, with no `filed` line of their own.
- Minor swe-pod/agents/swe-lead.md:44 Writes lists the code-repo merge as a lead write, but :58 forbids pushing `main` of a code repo (spec section 14 G1). Integrate step 4 (:346-350) should say that the human merges, or that the lead gives the human the merge commands in `depends` order.
- Minor swe-pod/agents/swe-lead.md:204 The lane table lets the lead file `decisions/` at any time, but Writes (:41-43) allows decisions only at integrate. Spec section 8 makes only `tests/`, `pod.yaml` and `changes/archive/` integrate-only. Make the two places agree.
- Minor swe-pod/agents/swe-lead.md:56 "Approve a spec ... without the human's word" reads as if the lead may approve a spec once the human gives the word. R8 says only the human approves, and :99 has the spec author record `approved:`. Make "approve a spec" an unconditional never.
- Minor swe-pod/agents/swe-lead.md:332 "Compare the latest evidence's commit_set with the current pins" is the wrong test for a named repo. Its commit_set holds the branch head, not the pin, so the two always differ. Compare `pod.yaml` and `tests/` at the evidence's space commit with their state now. The next sentence, "moved since that evidence", already describes the right test.
- Minor swe-pod/agents/swe-lead.md:10 The file has no `PROCESS.md §<n>` citations. Plan section 2.2 says role definitions cite PROCESS.md that way, and the five sibling definitions do. The lead's steps map to sections 11, 8 and 13.
