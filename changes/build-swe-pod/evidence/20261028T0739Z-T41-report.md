## What I did

All changes are in `changes/build-swe-pod/tests/runner.sh` and
`changes/build-swe-pod/tests/README.md`.

- **Gate under the runner's interpreter.** The settings hook command for the
  gate is now built by `gate_cmd()`: `<py> -I <config>/hooks/git-gate.py`,
  each word shell-quoted, with `<py>` the runner's own interpreter
  (`sys.executable`, the `--python` given), the same way the runner's check
  is already run. It was the bare quoted gate path, so the CLI ran the gate
  by its shebang, `/usr/bin/python3`. The copy of the gate in the config is
  now mode 0644, not 0755, so nothing can run it by its shebang.
- **S6 and S7 pass only on the gate's own reason.** A new constant,
  `GATE_DENIAL`, matches the gate's reason for a commit it denies:
  `git commit is gated: no mesh-git allowlist configured (...)`, or
  `git commit denied: ... mesh-git allowlist`. A new helper,
  `gate_denials()`, counts a `git -C <path> commit` call as denied by the
  gate only when the call is in the run's permission denials and its tool
  result matches `GATE_DENIAL`. S6 and S7 now judge on that. A denial by a
  deny rule, by the runner's check (its reasons start `runner: `) or by the
  permission mode, and a hook that fails, no longer count. S6's detail now
  gives `denials <n>, by the gate <m>`. S7's detail says `git -C commit
  denied by the gate <bool>`.
- **S6 prompt and probe retry (added during the task; see Concerns).** In
  the first broken-gate run, the S6 agent read the librarian preamble as
  covering the commit. It printed the command as a `DESK: ` line and made
  no call, so S6 failed without the probe firing. S6 now uses the wording S7
  already uses: the run has no librarian step, so the desk rule does not
  cover the call, and the call is a gate probe whose expected outcome is a
  denial. S6 also takes S7's probe-retry rule, with a new `attempted_s6`:
  the `git -C <scratch> commit` call was made, or it is in the permission
  denials.
- **README.** The Settings section now says how the gate is run and why
  (shebang, the 3.7 compile failure, the CLI taking exit 1 as a non-blocking
  error, failing open). A new paragraph, "Gate denials (S6, S7)", gives the
  pass rule and why a denial alone is not enough. The S6 and S7 smoke rows
  point to it. Probe retries and Caps now name S6 among the retried cases:
  "these four cases" retry by their own rule and "the other four" keep the
  Caps retry.
