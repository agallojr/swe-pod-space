## What I did

All changes are in `changes/build-swe-pod/tests/runner.sh` and
`changes/build-swe-pod/tests/README.md`. The runner gets a second
PreToolUse hook of its own, `hooks/runner-check.py`. It is held in
`runner.sh` as the string `RUNNER_CHECK`, written into the config at every
reset, and run with the runner's interpreter beside the git gate. It only
ever denies. It reads a Bash command by command position: it splits the line
into simple commands, skips here-document bodies, and looks past
assignments, shell keywords, wrappers and `bash`/`sh -c`.

- **a. Desk deny of mesh-post.** I removed `Bash(*mesh-post*)` and
  `Bash(*mesh-scan-loop*)` from `DESK_DENY`. `Bash(git:*)` and
  `Bash(gh:*)` stay. In a desk run, the runner check denies the mesh scripts
  only where they are the command: `mesh-post.sh ...`,
  `<path>/mesh-post.sh`, `bash <path>/mesh-post.sh`, and `sh -c '...'`. A
  read such as `cat .../skills/mesh-post/SKILL.md` now runs.
- **b. DESK lines in the final reply.** `DESK_PREAMBLE` now requires the
  final reply to repeat every `DESK: ` line, in order. I gave
  `LIBRARIAN_PREAMBLE` the same rule, since checks read the librarian's DESK
  lines from the final reply too.
- **c. git -C narrowed.** I removed the blanket `Bash(git -C:*)` deny. The
  runner check now allows `git -C <path>` only when `<path>` is a literal
  path inside the run dir. It denies any other path, and any path holding a
  variable, `~` or a glob. It also denies `git branch`, `checkout` and
  `reset` after any global options, which keeps the old `-C` coverage of
  those three. Add, commit and push at a path in the run dir go to the
  installed git gate, which denies them. Smoke S6 and S7 show the gate's
  denial.
- **d. A run ends at its result.** A new `wait_run` follows the stream while
  the process runs. When the `result` event arrives, the process gets 10 s
  (`RESULT_GRACE_S`) to exit, then the runner stops it. When a run ends, a
  new `stop_tree` stops the process group and every process under the agent
  process, found by parent pid, including processes that started their own
  session. A run counts as capped only when no result came by the cap.
  `summary-<k>.json` adds `result_s` and `stopped_after_result`.
- **e. Startup retry.** A run with no agent turn and no cap is a startup
  failure. That covers an empty stream, an exit at startup, and an error
  result with no turn, at any elapsed time. Only API retries until the cap
  is an API stall. Either one is retried once, after a 30 s pause
  (`STARTUP_RETRY_PAUSE_S`). The first attempt's files are kept as
  `stream-<k>-try1.jsonl` and `stderr-<k>-try1.txt`. The RESULT line ends
  `; step <k> retried once after <reason>)`. If the retry also gives no
  turn, the result is `error (no agent turn in step <k>; see
  stream-<k>.jsonl and stderr-<k>.txt)`.
- **f. Isolation and redaction.**
  - Each agent run's `$HOME` is now the run dir itself; for a smoke case,
    the case folder. The `XDG_*_HOME` variables are dropped.
  - The config dir is still passed explicitly. On macOS the sign-in is in
    the login keychain, which the CLI finds under `$HOME`. So the runner
    links only `Library/Keychains` from the node's home into the run dir for
    each agent run, and removes the link when the run ends.
  - The runner check denies any Read, Grep, Glob, Edit, Write or Bash call
    that names a `.agent-*` file in the node's home: by absolute path, by
    `~<user>/`, or by `cd <home>` followed by `.agent`. A plain
    `cat ~/.agent-identity.env` still runs, as the mesh-load skill does, but
    finds no file.
  - Redaction adds the CLI's dash-encoded form of every redacted path, with
    placeholders `<scratch-dashed>`, `<config-dashed>`, `<home-dashed>`,
    `<agent-cwd-dashed>`, `<cli-tmp-dashed>` and `<tmp-dashed>`. It also
    adds the CLI's temp folder `/tmp/claude-<uid>` as `<cli-tmp>`, and the
    node's per-user temp folder as `<tmp>`.
  - Redaction also replaces, as whole words, each registered `agent_id`,
    `agent_name` and `hostname` read from `--bus`, with `<agent-id>`,
    `<agent-name>` and `<host>`.
  - Smoke S8 now has the agent repeat the node's `$HOME`, the dash forms and
    the bus's cwds, ids and names. It checks that none survive redaction and
    that the agent's `$HOME` is the case folder.
- **g. Whole skill dirs.** A deliverable `<repo>:skills/<name>/SKILL.md` now
  exports `skills/<name>/` at the sha under test (`export_path`), so
  `check.sh` beside the space-librarian skill is installed with it.
- **Regression found and fixed during this task.** I first gave each run a
  scratch home at `<run>/agent-home/`. Smoke S1 then listed 25 skills
  instead of 16, plus an agent of the operator's own. The CLI looks for
  `.claude/` skill and agent folders in every folder above the cwd up to

## Concerns

- **Linux node untested.** Its sign-in is in the config dir, so the run dir
  as `$HOME` should work there. If the provider or the CLI needs anything
  else under `$HOME` on that node, smoke S1 fails at startup, and
  `HOME_LINKS` in `runner.sh` is where to add it. The lead's linux-server
  smoke will show this.
- **S1 does not fail on leaked skills.** The regression above showed only in
  S1's skill count (25 instead of 16), not in its verdict. The lead may want
  S1 to fail when the session holds a skill or agent that is neither
  bundled nor a deliverable. I kept S1's verdict as it was.
- **Still reachable.** The agent can still reach absolute paths outside the
  run dir with Read and Bash. Only the node's `.agent-*` files and `git -C`
  outside the run dir are denied, so a `cd <node home>/...` like the one in
  T2.TS2 still runs. Each agent run also has the macOS login keychain folder
  at `~/Library/Keychains`, as it had under the node's home before.
- **git -C semantics changed for test agents.** At a literal path inside the
  run dir, every git subcommand now runs except branch, checkout and reset
  (runner check) and add, commit and push (gate). For example, merge,
  rebase, stash and `submodule update` now run, as the `cd <repo> && git
  ...` form already did. `git -C "$VAR"` is denied with a message asking
  for a literal path. A test written when every `git -C` was denied may now
  give a different result.
- **Both preambles changed.** The final-reply rule is also in the
  librarian preamble, so every agent-mode test's prompt has changed.
- **Run dir contents.** On macOS the run dir now also holds `Library/`: the
  keychain link during a run, and the CLI's caches. A check that walks the
  run dir sees it.
- **Startup retry is still one try.** The retry pauses 30 s, so a gateway
  outage longer than that still ends in `error (no agent turn ...)` after
  one retry. The five smoke cases that use the runner's retry get the same
  pause.
- **Case files not filed.** The seven case files are not in the space; my
  lane for this task is `runner.sh` and `README.md`. To keep them as
  regression tests, they would have to be filed as tests.
